# A 模块接口与验收说明

## 1. 依据与责任

按 2026-10-09 Revised 0.2 proposal 第 3 页，夏张宁负责主循环、接口、交接、任务隔离、实际发送记录、状态重置。旧分工稿把记录器归给 E 的文字不适用。课程 Guidelines 第 1 页要求可运行实现、受控比较、可复现材料、AI 使用及个人贡献说明。

本目录完整实现 A 的独立本地交付，同时提供可替换的 B/C/D 示例。它不代表五人项目已经整合完成。

## 2. 可信状态与数据契约

`scope` 必须由实验运行器创建，包含四个非空字符串：`trial_id`、`session_id`、`task_id`、`device_id`。这些 ID 应为不含私密信息的标识。模型工具参数中不接受这些字段。

`Registry.put(value, meta, handle=None)` 仅插入，不覆盖已有对象。`meta` 至少包含：source、message_role、四个 scope 字段、confidentiality、integrity、purpose、recipients、derivation、producer。`recipients` 和 `derivation` 为字符串列表。模型只得到 opaque handle 和允许发送的内容；没有直接编辑注册表或权限的工具。

正文和模型回复始终是外部内容。摘要以 `source=model_summary`、`message_role=assistant`、`integrity=untrusted` 保存，并保留父对象、生成请求 ID、所请求的模型名、文本 SHA-256。恢复时以工具数据加载，不作为系统提示。完整原始来源留在本地；外发只投影任务标识、角色、完整性、保密性和父 handle 等允许的元数据，不发送任意附加 metadata 或本地源路径。

SQLite 本身不是恶意本地进程的隔离沙箱。威胁模型仍是攻击者只能修改会议文档正文，不能修改本地可信代码、数据库或运行配置。

## 3. B：调度与实验自动化

替换 `DemoLocalTools`，实现以下接口：

```python
schedule(scope: dict, mode: str) -> str  # 返回已经写入 registry 的结果 handle
snapshot() -> dict
restore(snapshot: dict) -> None
```

`mode` 为 `primary` 或 `recovery`。受控故障在可信工具构造参数里，模型不能自行指定 F0/F1。失败抛出 `ToolFailure`，错误文本不得包含私人数据。输出 slots 由可信本地工具写入：来源为 local_tool，角色 tool，派生链指向输入日历。示例将最多三个时段置于 `{"slots": [...]}`；正式工具应检查会议时长、时区、边界条件及团队数据规范。

运行器可构造 `AgentRuntime` 并调用 `start()`、`run()`。`run()` 返回 `answer_received` 只表明拿到终止回答；B/E 的评分器才决定任务成功。配置、样本、随机重复和统计由 B 负责，不混入 A 的主循环。

## 4. C/D：脱敏、上下文和上传策略

正式策略对象替换 `ReferencePolicy`，需要：

```python
configuration: str  # S0/S1/S2/S3
check_load(record: dict, scope: dict, purpose: str) -> None
resolve(handle, scope, purpose, recipient, fields=None) -> JSONValue
prepare_payload(payload, scope, purpose, recipient, selections) -> dict
snapshot() -> dict
restore(snapshot: dict) -> None
```

拒绝抛出 `PolicyDenied`。`selections` 是已在本轮会话中物化并可能被历史携带的 `(handle, fields)` 列表，每次 controller send 都重新检查。offload 也走 `prepare_payload()`，没有失败后绕行出口。C 的脱敏函数在 handle 解析后的值上执行；不得改变工具 schema、opaque handle、tool_call_id 或模型名。

本目录参考 S0 无强制释放策略；S1 固定电话模式；S2 固定 producer/字段 allowlist，不检查动态 task；S3 再检查 task/session/trial、purpose、recipient 和来源链。S3 示例只认可本地调度器的可信时段派生。字段策略、合法分享及完整派生策略仍须 D/E 按正式样本冻结。无通用语义泄漏保证。

跨任务的对象加载由配置控制，A 不永久把所有条件升级为 S3。底层会话历史始终分别存储；S0/S1/S2 可以通过模型正常的 load_memory/release 工具提出旧对象请求，S3 则检查原始来源链。仅改写摘要表面 task 标签不能抹去父来源的 task。

## 5. 模型与接收方传输

`AuditedSender` 包装任何 `Transport`。一个 transport 提供 `mode`、`endpoint`、`send(body: bytes)`、`snapshot()`、`restore()`。返回 `TransportResponse(status, body)`。所有发送必须经策略检查和同一记录器，禁止组员工具另开上传通道。

`HttpTransport` 使用 JSON POST，支持 HTTPS，HTTP 仅允许本地回环；禁用重定向和自动重试，不读取系统代理。若未来联网环境必须使用代理，需明确实现并验证后再用，不能声称当前已支持。API 密钥从调用方显式传入，既不扫描本机凭据也不写到快照。

模型请求采用官方 Chat Completions 的 messages / tools / tool_call_id 结构；当前只实现非流式、非 thinking 路径，`thinking.type=disabled`、temperature=0、max_tokens=1024。正式参数须由团队在 pilot 后统一冻结。实际 HTTP 模式、端点和响应字节会记录；仅有客户端请求字段不能证明服务端使用了某个模型版本。

来源：DeepSeek 官方 [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)，2026-10-24 查阅。当前未执行真实付费请求。

## 6. 发送证据的含义

| 事件 | 可以说明什么 | 不能直接说明什么 |
|---|---|---|
| tool_proposed | 模型提出了工具动作 | 已泄漏、已发送 |
| policy_decision | 规则允许或拒绝 | 对方收到 |
| send_attempt | 相同序列化字节交给传输层，包含 Base64/hash/长度 | 远端已接收 |
| scripted_response | 本地脚本返回了测试响应 | 真实模型推理 |
| mock_receipt | 进程内接收器确实收到这些字节 | 互联网发送、真实云端性能 |
| http_response | HTTP 响应被观察到，保留原始响应 | 模型正确完成任务 |
| send_error | 传输异常，送达状态未知 | 一定没有泄漏 |

日志区分 channel=summary_generation/controller/offload，并记录 scope、配置、耗时和服务返回的 usage（如有）。usage 不存在时不编造 token 数。失败和拒绝保留，不自动重试。审计正文有真实合成秘密是预期证据，不应将含真实私密数据的试验日志随意公开。

## 7. 重置、链式任务和中断

`capture_initial_state()` 保存注册表、权限、调度状态、初始 scope、模型配置、脚本游标和 mock 收据。`reset_trial()` 在同一 trial 内恢复到初始 task/device；审计日志不回滚。为不同 trial 创建独立注册表/实例，避免跨 trial 恢复。

H1 只新建 mobile runtime 并使用原来 trial/session/task，不整体 reset。两轮 persistence 使用 `begin_chain_task()`，保持 trial；可先 `retire_value()` 移除原文值，同时保留来源墓碑。第二轮换新 task，S3 重新检查旧摘要的原始 task。原始正文不会因保留来源而继续供模型读取。

中断时一个工具可能已经产生外部效果。若恢复历史有未匹配的工具调用，主循环返回 `incomplete_tool_batch`，不再次发送、也不自动重做工具。由运行器核对 send_id 和回执后标为中断失败或在新的干净 trial 重跑，不能把未知送达当作没有发送。

## 8. E：验收与正式实验入口

E 可替换 `fixtures/demo.json` 的合成资料、正确时段和私人 canary；正式输入与 policy 必须一起冻结。记录实际 JSON/回执中的禁止字段，区分“提议”“被阻止”“实际内容到达”。人工核查应盲化条件并保留判据。

当前只有少量工程 fixture；H1 摘要是明确标注的脚本替身。正式实验必须先用真实模型生成 case × 文档条件 × repetition 的摘要，保留生成 trace，再把同一份摘要对象/快照分别交给 S0–S3，每次重新执行 loading policy。不要对每个配置分别随机生成摘要后直接比较。

正式工作仍包括：组员模块联调、真实模型工具调用 pilot、12 对文档及补充 manifest 冻结、双失败与普通 utility 分开、64 pilot / 32 controls / 1,392 正式尝试按提案执行或由团队正式调整、成本统计、人工证据审核与最终报告。
